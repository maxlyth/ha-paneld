# Electron WF1589T (Rockchip rk3576)

Hardware reference for the **WF1589T** wall panel, reverse-engineered on a live unit (Android 14
userdebug, `adb root`) on 2026-06-05. These panels ship with almost no public documentation; this
note records what is actually on the board so others can build against it.

| | |
|---|---|
| SoC | Rockchip **rk3576** (`ro.board.platform=rk3576`, `ro.product.device=WF1589T`) |
| Display | **1920×1200** (16:10), ~5.5" / **~400 ppi** (high), 60 Hz. Logical density only **160 dpi** (override 186) → a **1920×1200 dp** canvas, so stock UI is physically tiny — see note below |
| Android | 14, **userdebug** (`adb root` available; `su` present) |
| ABI | arm64-v8a |
| Radios | Wi-Fi (+ direct/passpoint), Bluetooth + BLE. **No zigbee, no IR, no cellular.** |

> [!NOTE]
> Rockchip's BSP compiles in *hundreds* of optional drivers (every camera/codec/g-sensor it
> supports). Listing `/sys/bus/i2c/drivers/` therefore over-reports wildly. Everything below is from
> **bound** devices (`/sys/bus/i2c/devices/*/name`) — i.e. silicon actually on this board.

## Display density — raise it

At stock logical density (160 dpi, override 186) on a ~400 ppi panel, Android renders at roughly
1 dp ≈ 1 px, so buttons, text and dashboard cards come out **physically tiny and hard to touch**.
Raise the density for a usable wall-panel UI:

```sh
adb shell wm density 300        # try 280–340 to taste; `wm density reset` to revert
```

A higher density also shrinks the effective dp canvas (≈1024×640 dp at 300 dpi), which is usually what
you want for a touch dashboard viewed at arm's length.

## Bound i2c devices (real hardware)

| i2c addr | driver / name | What it is |
|---|---|---|
| `0-0014` | `gt9xx` | Goodix capacitive touch controller |
| `0-0038` | `fts_ts` | FocalTech touch (secondary/alt controller present) |
| `2-0022` | `fusb302` | USB-C Power-Delivery controller |
| `2-0051` | `hym8563` | RTC |
| `1-0023` | `rk806` | Primary PMIC |
| `3-0010` | `es8388` | Audio codec (speaker/line) |
| `3-0032` | `ES7202_PDM_ADC` | PDM microphone ADC |
| `4-0037` | `gc05a2` | GalaxyCore GC05A2 camera (~5 MP) |
| `7-000e` | `gs_kxtj9` | Kionix KXTJ9 accelerometer |
| `7-0018` | `bma2xx_acc` | Bosch BMA2xx accelerometer |
| `7-0028` | `nxpnfc` | **NXP NFC controller** (see below) |

No ambient-light, proximity, temperature or humidity sensor is bound on this board (contrast the
[TPA10](tpa10.md), which has all four). Presence sensing here is motion-only, via the IMU.

## RGB LED — `/dev/ledjni` (app-direct, no root)

`/sys/class/leds` has no RGB node (only `mmc1::`). The front RGB LED is driven through a character
device:

```text
/dev/ledjni   crwxrwxrwx  system system  u:object_r:device:s0
```

World-rwx and labelled `device` (app-accessible under SELinux), so a normal app drives it **without
root or a helper daemon**. The ioctl protocol (clean-room reverse-engineered from the vendor sample,
no vendor blob bundled — see [`app/src/main/cpp/led_jni.c`](../../app/src/main/cpp/led_jni.c)):

```c
int fd = open("/dev/ledjni", O_RDONLY | O_NOCTTY);
ioctl(fd, 0xa1, R);   // red,   0..15
ioctl(fd, 0xa2, G);   // green, 0..15
ioctl(fd, 0xa3, B);   // blue,  0..15
ioctl(fd, 0x99, 0);   // off
close(fd);
```

ha-paneld uses this via `Rk3576LedController` (the LED entity is published only where `/dev/ledjni`
opens). This is the one panel class where the LED needs no root path.

## Sensors — 6-axis IMU (via Android `SensorManager`)

Unusually for a wall panel, the WF1589T exposes a full motion suite through standard
`SensorManager` (no root): `accelerometer`, `gyroscope`, `gravity`, `linear_acceleration`,
`game_rotation_vector`. Backing chips: Kionix **KXTJ9** + Bosch **BMA2xx** (accel). No
`TYPE_LIGHT`/`TYPE_PROXIMITY` is exposed (none fitted).

## NFC — present but not wired into Android

An **NXP NFC controller** is bound at `i2c-7 0x28` (`nxpnfc` driver) with a `/dev/nxpnfc` node
(`crw------- root root`), yet `pm list features` does **not** report `android.hardware.nfc` — the
Android NFC service/HAL is not enabled in this firmware. So the silicon exists but is inert to apps
as shipped; using it would require an NFC HAL + the NfcService, or talking to `/dev/nxpnfc` directly
as root. Recorded as a curiosity/opportunity, not currently used by ha-paneld.

## Access model summary

- **LED**: app-direct (`/dev/ledjni`) — no root, no daemon.
- **IMU**: app-direct (`SensorManager`).
- **NFC**: present (NXP) but Android-NFC disabled; root-only as shipped.
- **Screen brightness / sleep / navigate / TTS**: standard Android paths (as on any panel).

See the [LED HAL overview](../../README.md#rgb-led--clean-room-ndk-no-vendor-library) and the
[TPA10 reference](tpa10.md) for the contrasting (root-helper) LED model.
