# ZHICAI SMT1019 (Rockchip rk3576)

> [!NOTE]
> The facts here come from a reporter's `/diag` dump and the retail listing (GitHub [#8](https://github.com/maxlyth/ha-paneld/issues/8)). The device has not been validated on hardware.

A ~10.1" rk3576 wall tablet sold as "Generic SMT1019 / RK3576_64GB" (manufacturer **ZHICAI TECHNOLOGY**). It is a different, more **locked-down** unit than the otherwise-similar rk3576 [WF1589T](wf1589t.md): it reports **no root** and a **firmware-restricted RGB LED**.

| | |
|---|---|
| SoC | Rockchip **rk3576** (`ro.product.device=WF2489T`) |
| Display | **1280×800**, ~10.1" |
| RAM / storage | ~4 GB / 64 GB (listing: "RK3576_64GB") |
| Android | 14 |
| ABI | arm64-v8a |
| Root | **none** — `su` is absent (`su -c id` exits 127) |
| SELinux | **Enforcing** (`getenforce`) — confines the LED ioctl to privileged domains |
| RGB LED | `/dev/ledjni` is present and opens `O_RDONLY` (`crw-rw-r-- system system u:object_r:device:s0`), but the LED **ioctl is denied** to sandboxed apps (`EACCES` / `rc=-13`); with no root there is no app-side path to drive it |
| Retail | [Amazon B0GSWXPB9K](https://www.amazon.com/dp/B0GSWXPB9K) |

## ha-paneld support

The bundled [`smt1019.yaml`](../../app/src/main/assets/device-profiles/smt1019.yaml) profile gives its tightly scoped `wf2489` device-substring branch priority over the WF1589T profile's broader `rk3576_u` model branch, so the observed `WF2489T` unit does not collide with the other rk3576 family. It declares:

- **`hardware.led.mechanism: rk3576-ioctl-daemon`** — the compiled ioctl driver is routed only through the authenticated root helper. Its live check keeps the LED unavailable and unpublished when that helper cannot drive the node, as on the reported no-`su` installation.
- **`platform.su_form: none`** — no app-accessible `su`, so root-gated features (evdev buttons, CPU governors, the `bl_power` screen-off path) are unavailable on the reported firmware.
- **`hardware.screen_off: brightness-zero`** — the no-root screen-off path.

Standard-Android capabilities (brightness, sleep, navigate, TTS, MQTT auto-discovery) work; the LED and hardware buttons do not on the reported installation. The vendor's own RGB control works because that app runs system-privileged; ha-paneld would need a working root/helper path or a firmware change to reach the same ioctl. If the supplier provides a firmware image, its SELinux policy and the LED node's permissions can be re-checked.

## WebView

The SMT1019 runs Android 14 with **no Google Play** (no GMS was detected), so the system WebView does not auto-update through Play. The stock WebView version shipped in the vendor firmware (`ZX-SMT1019-R157-V1.0A, 2026-02-05`) has not been established — the full ROM is a block-format OTA and extracting individual APKs requires a full `sdat2img` pipeline. If the stock build is old, a manual arm64 (`arm64-v8a`) SystemWebView sideload will be needed — the same class of fix as the NSPanel Pro/TPA10. If you have an SMT1019, run `adb shell dumpsys webviewupdate | grep "Current WebView"` on the stock firmware and report the version in [#8](https://github.com/maxlyth/ha-paneld/issues/8).
