# ZHICAI SMT1019 (Rockchip rk3576)

> [!NOTE]
> The facts here come from a reporter's `/diag` dump and the retail listing (GitHub [#8](https://github.com/maxlyth/ha-paneld/issues/8)), **not** a hands-on teardown like the other pages on this site. The device has not been validated on a unit here.

A ~10.1" rk3576 wall tablet sold as "Generic SMT1019 / RK3576_64GB" (manufacturer **ZHICAI TECHNOLOGY**). It is a different, more **locked-down** unit than the otherwise-similar rk3576 [WF1589T](wf1589t.md): it reports **no root** and a **firmware-restricted RGB LED**.

| | |
|---|---|
| SoC | Rockchip **rk3576** (`ro.product.device=WF2489T`) |
| Display | **1280×800**, ~10.1" |
| RAM / storage | ~4 GB / 64 GB (listing: "RK3576_64GB") |
| Android | 14 |
| ABI | arm64-v8a |
| Root | **none** — `su` is absent (`su -c id` exits 127) |
| SELinux | **Enforcing** (`getenforce`) — confines the LED ioctl to privileged domains |
| RGB LED | `/dev/ledjni` is present and opens `O_RDONLY` (`crw-rw-r-- system system u:object_r:device:s0`), but the LED **ioctl is denied** to sandboxed apps (`EACCES` / `rc=-13`); with no root there is no app-side path to drive it |
| Retail | [Amazon B0GSWXPB9K](https://www.amazon.com/dp/B0GSWXPB9K) |

## ha-paneld support

The [`Smt1019`](../../app/src/main/kotlin/io/github/maxlyth/hapaneld/device/Smt1019.kt) profile matches on `ro.product.device` `WF2489T` (before the WF1589T's `rk3576_u` clause, so the two rk3576 units don't collide) and declares:

- **`LedMechanism.NONE`** — the LED is firmware-locked and there is no root, so it is not probed or published (and no longer mis-reported as "RGB LED=ok").
- **`SuForm.NONE`** — no root, so root-gated features (evdev buttons, CPU governors, the `bl_power` screen-off path) are unavailable.
- **`ScreenOff.BRIGHTNESS_ZERO`** — the no-root screen-off path.

Standard-Android capabilities (brightness, sleep, navigate, TTS, MQTT auto-discovery) work; the LED and hardware buttons do not — a hardware/firmware constraint, not a software gap. The vendor's own RGB control works because that app runs system-privileged; ha-paneld would need a firmware change or root to reach the same ioctl. If the supplier provides a firmware image, its SELinux policy and the LED node's permissions can be re-checked.

## WebView

The SMT1019 runs Android 14 with **no Google Play** (`appCanSu=false`, no GMS detected), so the system WebView does not auto-update. The stock WebView version shipped in the vendor firmware (`ZX-SMT1019-R157-V1.0A, 2026-02-05`) has not been established — the full ROM is a block-format OTA and extracting individual APKs requires a full `sdat2img` pipeline (not yet run). If the stock build is old, a manual arm64 (`arm64-v8a`) SystemWebView sideload will be needed — the same class of fix as the NSPanel Pro/TPA10. If you have an SMT1019, run `adb shell dumpsys webviewupdate | grep "Current WebView"` on the stock firmware and report the version in [#8](https://github.com/maxlyth/ha-paneld/issues/8).
